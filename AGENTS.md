# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Rumbo product decisions

- September 22 collaboration: groups in Updates means teams. Team feeds aggregate accessible project and Route updates; custom sidebar groups do not define ownership. Updates may publish explicit status, Route priority, and manual reported-progress changes atomically with stale-value checks. Drafts never mutate work; manual progress remains distinct from calculated leaf completion. Replies use collapsible connecting lines (five levels), per-entry reactions and bounded attachments. Ask agent prepares a reviewed read-only chat draft only. Activity timelines show permission-filtered recorded events with historical before/after values and honest actor/source attribution, not subscriptions or fabricated backfill. Navigation icons and labels activate the same full row; tab color editing belongs in Settings, not ordinary tab clicks.

- September 21 team options: the sidebar team's three-dot dialog includes a direct Team settings destination for that exact team. Tooltips must escape scroll-fade masks without disabling fades; viewport-positioned overlays must not inherit transformed sidebar coordinates.

- September 20 Sub-routes: keep children as ordinary Routes with explicit parent links, exact workspace/project/team scope, sibling order, and at most five levels. New children never inherit completed acceptance or start agents. Use leaf-only progress, separate archived/cancelled work, and show unknown progress when related work is restricted or invalid. Archiving affects only the selected record; recover parents before children, and block deleting parents that still have children. Reparenting, retries, imports, rules, and approved agent proposals must preserve the same hierarchy and permission checks. Legacy invalid links require an explicit repair rather than silent data loss.

- September 20 Updates: one permission-aware activity store spans projects, Routes, requests, documents, outputs, milestones, and chats. Drafts are author-private and excluded from shared backups and published history. Publishing is one-way; revisions keep server-owned attribution. Imported published history does not grant the recorded author editing rights. The workspace feed supports filtered, bounded pages and stable thread links; mentions never send notifications or launch agents. Preserve older settings notes as explicitly historical records, not silent duplicates.

- Shared Changes & review belongs in Workbench, GitHub, projects, Routes, run/chat results and document history. Use one file-aware viewer with language icons, unified/split layout, expandable captured context and shared code appearance. Review comments and reviewed-file state belong to immutable snapshots; never carry approval to a changed version. GitHub-provided missing context is unavailable, not invented. Run diffs are observed before/after folder changes and may include concurrent edits, not proof of agent authorship. Reading never changes Git or launches agents; follow-ups are reviewed chat drafts. External reviews require existing connection permissions, explicit submission and stale-head checks.

- Teams use the searchable line-icon catalog only, not Unicode or uploaded emojis. Persist independent team color (identity marker) and icon tint; allow editing in team settings and directly from the team icon. Empty-state illustration tint is a separate browser-personal preference. Chat auto-follow is smooth by default, honors reduced motion, and pauses when reading older messages; keep ordinary wheel/touch scrolling native.

- Code & reviews offers a searchable light/dark syntax palette catalog and bundled monospace fonts, shared by GitHub and Workbench source/diff previews. Serve font files locally and preserve their licenses; load only fonts actually rendered. Keep legacy preferences valid, explicit reset, and truthful separation from terminal/UI typography. Push verified task-related changes to GitHub and maintain the Rumbo Dev Linear work record as requested.

- Connection detail refinement: primary Connect/Reauthorize (or runner account management) lives at the header’s right, with an honest setup link when blocked. Two large, provider-specific, noninteractive product previews precede Overview; native rendering keeps them sharp and theme-aware. Account scope/access and working settings remain below. Do not use generated mockups as interactive UI or claim the examples are live data.

- My Emojis uses workspace-scoped image uploads in Settings → Emojis (PNG/JPEG/WebP with crop/preview and bounded stored raster data). Reactions reference the saved emoji ID; messages use named shortcodes. Archived emojis remain readable in history but disappear from new selections. No uploaded SVG or external image URLs for custom emojis.

- September 20 universal scroll fades: every overflowing auto/scroll surface uses shared, theme-independent edge fades in both axes, proportional to hidden content. Clear the corresponding fade at a boundary and all masks when content fits. Preserve focus visibility, forced-colors access, nested scrolling, dynamic content, and resize behavior; never add an input-blocking overlay.

- September 20 connection details: all providers share a branded header, provider-specific workflow illustrations and overview, account/access setup, then organized settings. Keep official service marks and theme-aware native diagrams; label illustrations as non-live data. Preserve the real capability/action handlers and separate machine runner accounts from workspace OAuth. Do not imply configuring a connection authorizes it or enables unimplemented features.

- September 20: settings navigation fades subtly beneath its fixed search area as items scroll off the top. Remove the fade at scroll start; preserve theme colors, keyboard focus visibility, and forced-colors accessibility.

- September 19 Group 1: workspace OAuth connections are separate from existing machine/CLI accounts. Always show actual setup readiness; users authorize on provider sites, while operator app registration is a prerequisite. Encrypt new tokens, select resources explicitly, recheck authority on execution and queued work, preserve write idempotency through approvals, and never blindly retry uncertain writes. Native imports retain provenance and detect title/text conflicts; do not claim arbitrary two-way sync or full external-product editor parity.
- Governance uses four fixed management ranks and customizable capability roles, scopes, expiry and individual grants. Owners and Managers can administer connections by default; Admins require explicit policy/grants for connection administration. Owner promotion/leave and multi-owner protected operations require recorded electorate decisions. Optional local password identities/invitation links are implemented; email delivery, recovery, production identity hosting and arbitrary custom rank levels are not. Never treat a client-supplied actor ID as identity.
- GitHub source/diff appearance is personal browser state shared with Workbench: app/light/dark/high-contrast code themes, bounded monospace sizes, wrapping, line numbers, syntax highlighting, tab width, unified/split diffs and optional change markers. Settings have a live preview. Code browsing never changes a local checkout. Native Dock icon customization is not part of the web app.

- Slash commands use one typed, searchable registry across chat, replies, object updates, and Workbench. Catalog presence never implies execution: each surface must explicitly register handlers, show unavailable connection commands honestly, and preserve the same approval/permission checks as the equivalent button flow. Agent-starting, paid, external, and destructive effects are metadata and safety gates, never permission shortcuts. Workbench provides a separate reviewed Rumbo slash launcher; raw terminal input remains raw, so absolute paths such as `/usr/bin/git` are never intercepted.

- Project/Route/Request/document/output/milestone updates are persisted workspace-scoped activity, with typed updates and same-object threaded replies. Actor attribution and parent/target scope cannot be rewritten. `@agent` text is a mention or reviewed draft request only; imported or pasted text never starts an agent. Archiving an update is recoverable and uses optimistic versions.

- Keep the expanded sidebar workspace identity stationary across main and Settings: the same 34px approved mark, 4px name gap, typography, and top/left alignment.

- Settings navigation must visually share the main sidebar's responsive expanded width, 12px inset/rounded frame, neutral background, 14px labels, 18px icons, and 32px row cadence. Keep settings-specific destinations without switching to an edge-to-edge narrow rail.

- Sidebar uses one free top-level order: tabs and built-in groups can move above/below each other. Custom groups can be created/renamed/removed in Settings; removal returns children to the top level. Preserve exactly one placement, reload persistence, keyboard move controls, and reversible hiding. Sidebar movement never changes project/team ownership.

- Every Docs article has a distinct topic-specific line icon, shared between its card, search result, and article header. Maintain the explicit article icon registry and its coverage/geometry-uniqueness test; do not fall back to one category symbol for all articles.
