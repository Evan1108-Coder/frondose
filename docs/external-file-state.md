# External file state

The state badge beside an open file offers a local comparison and recovery copies. No GitHub connection or cloud service is required. Frondose checks visible editors every three seconds and on window focus/visibility changes. It can detect only saved disk edits, not another editor's unsaved buffer. A badge reports the last successful check, not an operating-system lock.

Clean buffers reload by default. Dirty buffers keep the original disk baseline, local draft, and observed disk snapshot. The comparison shows all three plus a proposed merged result. Every overlapping change needs an explicit Mine, Disk or Both choice. Applying a result changes only the draft; Save remains separate. Keep my draft explicitly acknowledges that a later Save replaces disk. Generated dependency lockfiles always require review, even with automatic non-overlap draft merging enabled.

Each apply rechecks the current draft and disk version. Each existing-file save fetches a fresh baseline, then uses the server's root revision, content version, staged write and final version check. A stale comparison never overwrites a newer draft. External writers are not transactionally isolated, so this is optimistic conflict protection, not a guarantee against an unrelated process writing in the final filesystem race window.

Missing, moved, inaccessible and permission failures preserve the draft. The existing file API cannot reliably distinguish those causes, so it says Unavailable instead of claiming that a file was deleted. New hosts expose conservative read-only permission-bit metadata and reject atomic replacement of files with no write bits. ACL, mount and other permission failures may still surface only during I/O. Legacy hosts without that metadata must be restarted safely to enable this extra server-side check; do not interrupt active terminal sessions just to do so.

Settings → Code appearance → External file changes has automatic clean reload (on), optional automatic non-overlap merging into drafts (off), and local recovery (on). Preferences belong to this browser/app profile. Recovery uses IndexedDB on this device, containing plaintext file text, scoped to workspace ID, directory revision and relative path. Up to 20 copies total, four per file and 12 MiB of text are retained; individual versions are bounded to 512000 UTF-8 bytes. Unsaved text is debounced for 800 ms; sudden termination or unavailable/full browser storage can prevent a copy. This is not a backup service. Disabling recovery stops new copies but does not erase existing ones. Before replacing a draft, enabled recovery must succeed; otherwise the action stops with a download alternative. A copy restores as a draft against a fresh disk baseline (unsaved unless identical to disk), never with old disk authority. If disk is unavailable, copies can still be downloaded.

Merge computation uses a dedicated terminating worker, bounded input/line counts and a 2.5-second timeout. The line-based algorithm is [node-diff3 3.2.1](https://github.com/bhousel/node-diff3), MIT; its full notice is bundled at `/licenses/node-diff3-MIT.md`. CRLF and trailing-newline data are retained. If comparison exceeds limits, keep/download the draft and use an external editor.

Activation: publish the new hashed frontend assets without deleting old assets or restarting the live server. The packaged Mac application includes current backend permission checks for its next safe host startup. Updating/reopening a window attached to an older external host does not replace that host's in-memory code.
