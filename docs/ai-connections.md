# AI connections: implemented paths and setup

Rumbo distinguishes a provider account from an agent profile. One authorization can later serve multiple profiles, but an agent's instructions, context, tools and run approvals are separate. The local development server is loopback-only and must not be exposed publicly.

| Provider | End-user route | Rumbo state | Who pays for model usage |
| --- | --- | --- | --- |
| OpenRouter | Browser sign-in with PKCE; a user-controlled key is returned to Rumbo | Authorization, encrypted storage, key check, user-filtered model list and explicit short test implemented; agent execution not wired | User's OpenRouter account/credits |
| Hugging Face Inference | OAuth with `inference-api` scope | PKCE authorization, encrypted token, refresh when available, account/model checks and explicit test implemented; operator OAuth app and agent execution still needed | User's Hugging Face account/allowance |
| GitHub Copilot | GitHub OAuth user token to server-side Copilot SDK | Planned; OAuth app, isolated hosted SDK runtime and user-subscription check still needed | User's Copilot subscription/limits |
| Codex and Claude Code | Existing locally signed-in runner | Implemented for local machine only, not a hosted visitor OAuth account | User's existing provider account, subject to its terms/limits |
| Direct OpenAI, Anthropic, Gemini, xAI, Mistral, DeepSeek, Groq and similar APIs | Typically API credentials or operator-funded API billing | No public one-click Rumbo connection has been verified | Credential/account owner or Rumbo operator |

OpenRouter's user authorization requires no operator API key. The user chooses **Connect OpenRouter**, signs in at OpenRouter, and is returned to Rumbo. Rumbo binds the ten-minute attempt to the current signed-in actor, workspace and callback origin. It stores the returned key encrypted and checks `/api/v1/key`. **Check authorization** makes a read-only provider request. **Choose model to test** loads OpenRouter's user-filtered catalog and only the explicit **Send test request** action makes a small inference call that can cost credits. Removing the connection deletes Rumbo's copy; users who want remote invalidation must revoke that key at OpenRouter.

For public deployment, Rumbo needs a production identity/session service, HTTPS origin and callback routing, secret-key management and isolated provider token storage, production monitoring, and an end-to-end test with an owner-approved non-production account. Set `RUMBO_PUBLIC_BASE_URL` to the exact HTTPS origin after the public server's current loopback-only host policy is replaced by a separately reviewed deployment policy. Do not change the loopback policy merely to make this prototype reachable. Hugging Face additionally needs an OAuth app with the exact `https://<origin>/api/ai-connections/huggingface/callback` redirect and `inference-api` scope; set its client ID as `RUMBO_HF_CLIENT_ID` and, if using a confidential client, its secret as `RUMBO_HF_CLIENT_SECRET` in server-only configuration. The browser never receives this secret. GitHub Copilot additionally needs a GitHub OAuth/GitHub App and server-side Copilot SDK runtime, with each user having an eligible subscription.

The current OpenRouter and Hugging Face connections do **not** make these accounts available in Rumbo Agent or Workflows. Routing reviewed context, permissions, history, usage and failure states through a provider-independent execution adapter is the next vertical slice. No automatic fallback to another provider is allowed.
