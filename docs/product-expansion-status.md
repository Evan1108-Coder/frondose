# Rumbo product expansion — implementation and limits

Updated September 26, 2026. This is a coverage ledger, not a statement that every roadmap item is finished. Rumbo is moving toward a solo-first personal AI work environment through the [ordered vertical slices](solo-ai-direction.md). The app remains a **localhost development product**, with optional local accounts and enforced workspace access. Automated and isolated QA must not connect real AI accounts, invoke paid agents or populate the user's real workspace.

## September 26: Rumbo Agent

Sidebar follow-up: Today → Rumbo Agent is the fixed top-level order. Rumbo Agent cannot be hidden or grouped; legacy layouts restore that placement without resetting unrelated customization. If Today is hidden, Rumbo Agent is first. The customization editor and context menu explain the fixed placement. Verified with 872/872 tests, production build, and desktop/mobile save-and-reload browser checks using the isolated QA workspace.

The dedicated assistant surface builds on the existing conversation/run/context services. It remains visible without a connected provider. Chat creation is explicit and idempotent, uses a shared Codex or Claude connection, and does not itself invoke AI. Chat titles use the first submitted message rather than a hidden model invocation. Conversation management, contextual entry points and dedicated defaults are provided without changing provider credentials or granting tools. Contextual requests retain stable source references; restricted or revoked source content must not remain accessible through derived conversation history.

Models are provider defaults and configured identifiers, not an exhaustive account-verified catalog. Native tools remain explicit per-run opt-in, and all workspace writes require review. This does not provide unrestricted workspace/file access or new provider integrations. Real-account validation remains out of scope; verification uses isolated injected providers.

Dedicated settings control model/reasoning, memory, conversation history, Context Packs and a bounded workspace overview. The overview includes permission-filtered Area/project/Route summaries and document titles, not full documents or an assertion that the assistant knows everything. The exact reviewed manifest discloses limits and omissions. Captured source restrictions propagate to conversation messages, runs, outputs and related activity. Conversation exports recheck access. Chats with retained source-dependent runs/results can be archived but cannot be permanently deleted until a future explicit history-deletion design can preserve that boundary. Messages referenced by retained outputs also cannot be deleted. Branching or document conversion that would lose protected provenance is unavailable.

## Solo-first transition: Areas slice

The first implementation slice reuses existing Team identities as **Areas**, domains such as Product, Engineering, Research or Personal administration. Existing projects, Routes, updates, documents, resource references, contacts, grants and history keep their relationships. Legacy `teams`/`team_id` storage and links remain compatible rather than generating replacement identities.

Additive Area settings store instructions, default workspace agents, Context Packs, read-tool preferences, review-only policy and optional Contacts visibility. Contacts are a directory, not a required human team or an account system. Existing entries remain stored when Contacts is hidden. Workspace export/import includes these scoped defaults, remaps their references and retains review-only policy. See [schema and backup notes](schema.md).

**Boundary:** saved defaults do not grant tools or execution authority. Selected Area instructions and Context Packs now enter the reviewed Context Inspector through the current access boundary. Existing plans/templates are not relabeled as a completed multi-agent Workflow.

September 24 continuation closes the original profile/launch gaps: profiles share provider connections while independently specifying role, instructions, model, supported reasoning, memory, context packs, output behavior and permissions. Runs pin profile versions. Agent Studio provides safe unbound copies/imports, explicit provider readiness, histories, memory and associated Skills. No ordinary provider chat history is imported and no live account was used for verification.

The Context Inspector previews the exact Rumbo-supplied prompt, source exclusions/truncation and execution boundary. Launch rechecks the selected input and source fingerprint, uses the reviewed prompt verbatim, and saves an immutable run snapshot. Previews expire after ten minutes and cannot cross actors/workspaces or be reused for another run. Current source access is rechecked on snapshot reads. Older API callers compile/capture context without the interactive review; new session/chat controls require review. Provider-owned system instructions and later granted project-file reads are outside the snapshot. Native tool names remain unavailable by default; an explicitly opted-in reviewed live run shows the exact bounded contracts available to its private bridge.

Manual Workflows connect immutable definitions and typed inputs to canonical agent/Skill runs, exact saved output handoffs, conditions, bounded retries and two separate human decision gates. The feature-request starter covers Researcher → Planner → plan approval → Builder → Reviewer → output acceptance → approved knowledge. Creating, previewing or opening a run never starts a provider. Each agent attempt is prepared, context-reviewed and explicitly launched; completion is reconciled from the canonical run, not a submitted completion claim. Knowledge finalization copies the exact currently approved output version after a fresh attributable human review. Canonical provider reports supply recorded usage where available, not account billing or token/cost enforcement. Per-step provider execution time is bounded, with setup and termination grace disclosed separately.

Workflows retain historical and current source permissions when document/Skill/output context is copied into attachments. Cached retries recheck authority. Imports preserve reusable definitions with remapped references, paused state and read-only permissions, while excluding run reservations, approvals and process bindings. Legacy work plans and supervised repeating Routes remain accessible without being relabeled as executable Workflows. The full seven-step path is tested with isolated injected providers only; real-account execution is deliberately unverified.

Today provides a read-only command center with Area/Project filters, decisions, active execution, review-needed outputs, explicit next actions and recent context. Failure groups use recorded codes only; due knowledge and outdated Workflow profile pins have inspectable warnings. Prepared/expired/retryable Workflows are never presented as running work. Snoozing, Following, Recent, Activity and check-ins remain browser-personal. Native review history is authority-checked even for older completed runs. The Today API makes no provider calls or workspace mutations.

Skill evaluation evidence now binds stable cases to explicit reviewed-context launches, canonical runs, pinned profile versions and exact recorded reply/output artifacts. Human pass/fail assessments are immutable and separate from provider completion. New Skill publication requires current-version coverage for every case; legacy handwritten notes do not satisfy it. Same-input comparisons retain both artifacts and captured configuration without claiming a controlled benchmark. Revoked context/output access also blocks evidence reads, publication and cached replays. New output reviews record the server actor separately from typed attribution; legacy/imported reviews retain unknown server identity.

Routes can explicitly opt into evidence policy 2. Every current acceptance criterion needs a human Pass assessment tied to the exact agreement, output version and recorded artifact before a separate output approval. Changed criteria or versions invalidate current coverage without erasing history. Immutable accepted checklists preserve the evidence referenced at approval. Historical and current source access are checked on reads, decisions and retries; revoked latest evidence never falls back to an older pass. Workspace imports preserve this stricter policy but not assessments or approval authority. Existing manual checklists remain compatible until explicit opt-in. This is evidence-backed human review, not automatic verification of provider claims.

Agent Studio now compares saved instruction versions, exposes known/unknown authors and restoration provenance, and previews selected text before saving a new immutable version. Restoration excludes provider/runtime/context/permission settings, rechecks current and source access and uses actor-bound idempotency. Skill definition comparison shows exact instruction, input, tool, example, test and review-policy changes with shared code settings. Comparisons are not performance claims and do not transfer test results or approval.

Recorded run usage now has a separate immutable invocation/report ledger, preserved launch scope, permission-filtered detail and agent/project/Workflow aggregation. Adapter terminal reports are captured even after the display-event cap. Metrics distinguish known zero from unknown, partial and ambiguous reports, and expose per-metric coverage rather than pretending the known subtotal is complete. Claude main-loop/all-model counters stay separate; client cost estimates are explicitly not billing. Simulations and prepared Workflow attempts contribute no measured invocation. No account probes, account balance, subscription allowance or budget enforcement is implemented.

Knowledge conflict review now preserves exact approved-entry snapshots and human reports/decisions. Fresh version/hash and historical/current read/write checks protect explicit keep-both or supersede-one decisions; stale pairs cannot be decided. The optional scan is a bounded literal title/scope/type comparison, not semantic truth verification. A report never changes approval or excludes context automatically. Relevant notices enter an exact run prompt only when both sources are already included; earlier captures remain immutable and readable only with current and historical access. Separate agent memories are not scanned. Dismissing an obsolete stale report is not yet implemented.

Workbench now has durable manual text-file checkpoints and selected-file restore previews. Recovery checkpoints and restore intents persist before filesystem writes. Current state/hash/mode, physical root identity, current/historical authorization and active project execution are checked; exact retries return recorded results rather than reapplying writes. Git index/history and omitted files are untouched. Multi-file restores may be partial and external filesystem writers are not transactionally isolated. These checkpoints do not replace full backups or automatically wrap provider runs.

This is a bounded supervised solo-AI release. Universal selection-to-agent actions, broader semantic/agent-memory conflict detection and background orchestration remain future work. Existing rules, repeating Routes and manual Workflow steps remain explicitly supervised. Native-tool live-provider compatibility also remains unverified; no real account was used for tests.

## What you can use now

### Shared changes and reviews (September 20, 2026)

Workbench, project Changes, Routes, session/chat results, GitHub pull requests and document revision history share a file-aware comparison component. Library output and knowledge-version comparisons reuse it, and quoted Markdown patches are labeled as unverified text. Chat/document code blocks follow the same personal code appearance. File-type badges, unified/split layouts, expanded captured context, search, wrapping and whitespace filtering are supported.

Repository/document review snapshots persist exact versions, line comments and per-person reviewed-file state. Project views aggregate linked snapshots; copyable links retain the snapshot ID and recheck access. Local Git supports working, staged and two-ref comparisons without changing the checkout. Eligible future live runs attempt before/after capture of the linked default Git folder; concurrent edits can be included, so this is observation rather than authorship proof. Agent follow-ups save editable chat drafts and never launch an agent automatically.

GitHub supports PR patches, inline discussions, reviews and checks plus explicit Comment/Approve/Request changes submissions (including a selected line). Existing enabled-feature permissions and exact-action owner approvals apply. Stale heads are rejected; same browser-tab retries retain their request key. Real GitHub authorization and review submission remain **not live-verified**. Provider-provided absent context is not fabricated.

Limits: local/PR review previews are bounded to 200 files, approximately 2 MB total patch text and 300 KB per file. Private paths, symlinks, large and binary files are excluded or explained, not silently called fully reviewed. Large visible patches render in 1,000-row increments. Snapshots/comments persist in the database but are not yet included in workspace JSON export/import. Review markers are not approvals, Git merges, or Route completion. No public deployment is implied.

### Governance and Group 1 connections

Local account setup, password sign-in, session revocation, one-use copied invitation links, four management ranks, custom permission roles, individual grants/denies, team/project/connection scopes and expiry are implemented. Owner promotions and departures use owner-electorate approvals. Multi-owner destructive workspace actions and high-impact external actions require exact-target approvals. Delegated agents cannot approve requests, elevate privileges, see tokens, or act after their sponsor loses permission.

The marketplace includes fourteen entries: existing Codex/Claude runners and twelve SaaS adapters. OAuth registration is an operator prerequisite; the UI exposes it explicitly. Available provider-specific operations, OAuth requirements, and limitations are listed in `server/connectors/README.md`. Per-connection settings control selected resources, enabled actions, agent allowlists, cached imports, conflict handling, durable read jobs, scheduled reconciliation and supported signed webhooks. GitHub adds remote code browsing/comparison; Code & reviews adds shared personal code-display preferences.

Not complete: arbitrary custom management-rank levels; temporary rank promotions (temporary permission grants are implemented); email invitations and recovery; public deployment; general two-way field synchronization; full native Slides/Sheets/Figma editing; autonomous multi-step agent tools. Current agent actions are bounded, reviewed final-reply proposals. Provider account compatibility still needs live verification after operator registrations. Do not infer these missing features from the connection catalog.

### Workbench

Open Workbench from the sidebar or a project. A project without a folder still has a planning overview. Explicitly linked folders enable a scoped file tree, filename/content search, text preview, pins, Git status and diffs, branch/worktree inspection, and deliberate worktree creation. A worktree must belong to the project's repository; it does not switch the project's working folder silently.

Real xterm terminals use node-pty, with resize, input, stopping, retained output, and reload recovery. Saved commands and discovered package scripts require a confirmation before running. There is no background command execution merely from opening the page. The local preview checker validates an explicitly chosen localhost port; it does not deploy a project.

Settings inside each Workbench persist panel visibility, file wrapping, terminal font size and terminal count limit. Settings → Workbench explains the boundary and links to project environments.

**Important:** terminals run as the current OS user, not in a sandbox. Closing their panel is not stopping their process. Server restart ends live processes; saved history remains. Workbench has bounded output and basic sensitive-file/path protections, not an assurance that arbitrary shell commands are safe.

### Connected work and review

Route work agreements hold a human owner, required reviewer, expected output type, acceptance checklist, parent route and blocking dependencies. Parent/dependency cycles are rejected. Outputs link back to a route, project, source conversation or producing run.

Library has versioned outputs, comparison with the previous version, quote-anchored comments, resolution/reopening, named review decisions, and Markdown export. Approval requires the current version and linked acceptance criteria. A new version needs a new review. Requested changes create a linked revision Route with feedback; they do not dispatch an agent, merge Git changes or mark the original work complete automatically. Reviewer names are recorded attribution, **not authenticated signatures**.

Projects have direction/scope/success/exclusion fields, explained health, owned risks/questions, a retrospective and milestone acceptance criteria. The timeline uses real project dates, route due dates and milestone targets, lists undated work separately, and flags an unfinished dependency whose due date is later than the dependent route. It is a date map, not a forecast or an automatic scheduling engine.

### Context and conversations

Agent awareness now supplies up to 30 recent projects, routes, teams and document titles plus interface preferences and recent action outcomes on each eligible live reply. Context remains bounded and can be disabled in Settings → Agent awareness. It does not include credentials or automatically read document contents. Extremely long prompts can exhaust the context budget and omit awareness.

Completed replies can propose allowlisted preference updates, project/route/document edits, reversible archives and persistent memory creation. All requests require an authored human review dialog; unsupported actions, cross-workspace targets, archived parents, stale values, active-session changes and repeated decisions are rejected by the server. This final-reply proposal protocol remains available when native tools are not selected; it is separate from the run-private MCP bridge. Provider compatibility is tested with injected responses only. Approval does not automatically start another paid run.

### Run-private native tools (September 24, 2026)

A reviewed live Codex or Claude run may explicitly enable native tools. Rumbo creates one private Unix-socket bridge for that canonical run, passes its random capability only through the child environment, configures only the generated `rumbo` MCP server, and revokes the bridge on stop, completion, expiry or startup failure. The MCP adapter exposes only initialize/ping/list/call, with bounded definitions, messages, calls, concurrency and deadlines. It writes no provider/global configuration and has no browser tool-call endpoint.

The six read tools search or return only captured sections from the reviewed run manifest; they do not browse the current database broadly. Authority is derived from persisted run/profile/sponsor/context records and rechecks source and scope access. The six write tools create idempotent pending human-review requests. Approved handlers may create a draft Route, apply an allowlisted Project patch, create a draft memory candidate or create a review-needed output/version. Permission approval explicitly grants nothing, and handoff approval launches nothing. An agent cannot approve its own request; stale targets, changed input under the same key, missing sponsor/reviewer permission and revoked context fail closed. Tool calls and decisions remain auditable but are not exported as portable authority.

Focused native-tool, transport and provider-adapter tests use temporary databases, injected processes and the local test socket only. They are green. The post-slice full suite, production build and browser checks are still pending at this point in the ledger, and no real Codex/Claude account or paid provider run was used.

Approved memories are scoped by workspace, agent and optional project. Chat context and Agent awareness settings show their contents and provide confirmed forgetting. Disabling saved memory excludes them from subsequent prompts. Existing conversations are not erased. These new memory/action tables persist across restarts but are not yet included in workspace JSON export/import; database backups remain necessary to preserve them. Public multi-user authorization is still not implemented.

The conversation list resizes by dragging its right edge, folds below a threshold and automatically folds on narrow containers; a labeled button restores it. Chat context has padded sections, bounded scrolling and a fixed footer. Agent progress is separated when the provider marks commentary, folds after completion, and remains reopenable. Provider failures use short explanations with expandable diagnostics; a 403 still requires resolving provider access, not just changing UI.

Conversation additions include replies/threads, quotation, bookmarks, visible recipient and access mode, queued follow-up **drafts**, branch-from-message history, project moves with context warnings, context previews and immutable context selection, and message conversion to Routes/documents/outputs/memory. Branches and drafts never run agents automatically. General discussion needs no folder; coding still requires a chosen working location.

The send/retry pipeline is tested with injected provider implementations: duplicate protection, restart persistence, failed/empty replies, stops and strict context attachment validation. **Real Codex/Claude replies and current account compatibility still need the owner's test.**

Message actions now include explicit multi-selection, copy/export and cancellation. Hover or keyboard focus exposes React. The reaction picker has 253 distinct line icons (16 original Rumbo glyphs plus Lucide), 631 Unicode emojis, searchable categories, preset icon colors and custom hex tints. Reactions persist through reload and workspace export/import with scope checks. General-chat Codex launch overrides no longer recreate transportless MCP entries when user configuration is ignored; failed configuration and empty replies remain explicit errors. No global provider configuration was edited.

### Pictures, resources and visual feedback

Project and profile pictures accept PNG/JPEG/WebP upload or drag/drop, then a custom crop, zoom and reposition dialog. Saved pictures are bounded 512px thumbnails. Teams have a Resources overview section and a dedicated tab for files, images, audio/video, safe URLs, GitHub branch links and Rumbo references. Resources support search, editing, archive/restore and explicitly confirmed deletion after archive. File limits are 25 MB each and 250 MB per workspace. URL favicons are requested directly from the linked site's origin, not by the server.

Team sidebar children deep-link to each section. Navigation is darker than the canvas. A 57-composition catalog gives empty states distinct monochrome illustrations, now rendered through four static, theme-aware oblique relief scenes (`docs/empty-state-visual-style.md`); shared Lucide/Morphicons glyphs have semantic pointer feedback, including decelerating gears and head-first arrows. Keyboard activation is immediate, and reduced-motion preferences cancel travel/morph feedback. The Home setup checklist has been removed.

Library knowledge distinguishes facts, decisions, preferences and instructions; supports draft/approved/superseded states, rationale and review dates; and can be archived/restored. Editing approved content resets approval. Revision history uses the recorded change log, including pre-edit text, and can restore text into an unsaved draft. History begins with change logging; it is not retroactively reconstructed or tamper-proof. Library snapshot backlinks show where the entry was captured. Restoring knowledge never rewrites frozen snapshots.

### Organization and coordination

- Home: attention/active/ready work, project grouping, snooze/bring-back, followed projects, recent places, activity and a check-in change count. Preferences are per browser/workspace.
- Coordination: persisted work plans, prerequisite gates, human/agent assignments, explicit session preparation, result/handoff records, pause/resume, queue, handoffs, requests, saved queries, goals and templates. Prepare opens a session form; users still review and launch it themselves. Linking a resulting run to a plan step is currently explicit, not automatic.
- Repeating Routes: persisted interval/date schedules, pause/resume, deliberate generation of a due occurrence, optimistic concurrency and request replay protection. **This is supervised recurrence, not a background scheduler.** It never schedules an AI run. Duplicate and split actions copy briefs/checklists into new unassigned Ready routes without losing the source.
- Sidebar: hide individual projects, teams, agents, chats and saved views; restore them in customization. Hiding is a personal presentation preference, not archive or permission control. Saved queries open directly from the sidebar.
- Favorites: projects, teams, routes, chats, agents, memory, outputs, runs, Workbench projects, documents and saved views. Not every resource type is pinnable yet.
- Search: workspace-wide content plus `type:`, `project:` and `status:` filters, excerpts and message deep links. Documents and saved views now have permanent in-app pages and links rather than editor-only access.
- Back/forward: a bounded, workspace-local in-app navigation history and `Cmd/Ctrl [` / `Cmd/Ctrl ]`. It resets when changing workspace or reloading and does not navigate outside Rumbo.

### Import, settings and safety

Operational pages are reachable outside Settings. Settings configures Home, coordination, output-review policy, Workbench and existing workspace resources. Consequential command execution and review decisions remain explicit.

Workspace export/restore includes the new workflow content, message bookmarks, validated reactions and project pictures. Imports validate and remap references inside a transaction and create a **new** workspace. Folder grants, credentials, active runs and terminal permissions are never restored. Outputs require fresh review, approved knowledge becomes draft, work plans and repeat schedules are paused, and completed/dispatched plan states are reset. Library snapshots retain their captured text; stale references require new review. Chat follow-up drafts, branch relationships and the full change-log/knowledge revision history are not restored. Team Resource uploads are not part of the workspace JSON archive; download those files individually. Imported message text is not reinterpreted as trusted current agent context.
