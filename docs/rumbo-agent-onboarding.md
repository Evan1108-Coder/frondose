# Rumbo Agent first-use setup

Rumbo Agent now opens a full-page setup on a workspace's first visit before it can create a provider profile or new conversation. The four required choices are a display name, one of six orb colors, a purpose, and behavioral guidelines. Saving setup does **not** sign in to an AI provider, create a provider account or profile, or start a run. Codex or Claude Code must still be connected separately before a new conversation can use them.
The “Not now” action returns to Today without saving or creating a profile; entering Rumbo Agent again resumes the first-use gate.

The orb is a set of six generated transparent images served by Rumbo from `/agent-orbs/`. Color changes only the visual identity; it does not change the provider, model, pricing, data access or permissions. The onboarding view has a restrained pointer-following halo and a dim code-text atmosphere behind the artwork. `prefers-reduced-motion` disables arrival motion and pointer-dependent halo movement.

Identity is saved in the workspace-scoped `rumboAgent:<workspace-id>` preference record as `display_name`, `orb_color`, `purpose`, `guidelines`, and `onboarding_complete`. An existing workspace with a Rumbo Agent preference record, deterministic profile, or saved Rumbo Agent chat is treated as legacy-complete so an upgrade does not block its prior work. Saved conversations remain readable even if setup cannot load; setup gates only new profile/chat creation. Completed setup cannot be reset through the preference endpoint.

Purpose and guidelines are **not merely presentation**: when a Rumbo Agent profile is created, they are inserted into its instructions with explicit untrusted-guidance markers. Later edits update existing Rumbo Agent profiles in a savepoint and bump their immutable profile versions. The exact context inspector includes the resulting profile instructions before a send; existing run history keeps its captured version. These user-written guidelines never grant tools or permissions and cannot override the base rule to use reviewed context and propose changes for human review. The API rejects reserved markers, control characters, unsupported colors, and missing first-use purpose/guidelines. Editing an existing profile also requires `agents.write` permission; saving workspace preferences requires `workspace.write`.

Preferences remain editable under Settings → Rumbo Agent. First-use setup itself is mandatory for a new workspace, but legacy users are not forced to invent answers to continue using a previously working assistant. If a legacy user leaves purpose/guidelines blank, edits to other preferences remain possible.

For other UI surfaces (such as the sidebar), import `RumboAgentOrb` from `src/components/RumboAgentOrb.jsx` and render `<RumboAgentOrb color={appearance.orb_color} compact />`. Import `useRumboAgentAppearance` from `src/lib/rumbo-agent-appearance.js` and call it with the current workspace ID; it returns only `{ display_name, orb_color }`, defaults to blue, and receives same-tab preference changes immediately. The hook makes only a read-only API request and does not provision an Agent.

Verification: `node --test tests/rumbo-agent-api.test.mjs` covers first-use gates, no hidden provider calls, required fields, guidance in the reviewed prompt, profile version updates, and existing conversation behavior. `npm run build` verifies the React UI and generated assets are bundled. This does not certify real-provider billing or public-hosted execution: Rumbo Agent still uses the available local Codex/Claude runner path.
